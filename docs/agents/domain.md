# Domain docs

This repo uses a single-context layout: `CONTEXT.md` at the root and ADRs in `docs/adr/`.

Before exploring an area, read the root `CONTEXT.md` and any relevant ADRs. These files may not exist yet; proceed when absent. Create them through the domain-modeling workflow when terms or decisions are established.

Use glossary terms from `CONTEXT.md` in issues, proposals, hypotheses, and tests. If a needed concept is missing, check the project's language and record a real gap for domain modeling.

If a proposed change conflicts with an ADR, identify the ADR and explain why the decision should be reconsidered.
